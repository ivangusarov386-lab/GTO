# Пароль судей: установка и проверка

Изменения подготовлены для проверки перед публикацией. Репозиторий сам по себе не обновляет Google Apps Script. Главный лист (`Code.gs (list)`) не изменяется.

## Состав проектов

- «все нормативы»: существующий код заменить содержимым `Gode.gs (norm)`, добавить файл `JudgeAuth.gs`.
- «Длинная»: существующий код заменить содержимым `Code.gs (run)`, добавить отдельные файлы с содержимым `Code.gs (pushup)` и `JudgeAuth.gs`. В проекте должна остаться ровно одна функция `doPost` — из файла run. Обработчик отжиманий теперь называется `handlePushup_` и вызывается общей точкой входа. Функция ручного сброса сохранена; не запускать её для настройки доступа.
- «главный лист»: ничего не менять.

## Настройка таблицы

Один раз выполнить `setupJudgeAccess` из редактора любого из двух изменённых проектов. Функция создаёт лист «Доступ», подписи и случайный служебный ключ, не очищает результаты и не заменяет существующий пароль.

На листе «Доступ» в B1 установить общий пароль (формат ячейки — текст). B2 — служебный ключ; его нельзя публиковать или передавать судьям. Саму таблицу оставлять доступной только ответственным сотрудникам. Не открывать доступ по ссылке для работы судей. Пустой B1 запрещает вход. Для смены пароля достаточно отредактировать B1. Изменение B2 дополнительно отзывает все сеансы, в том числе если возвращаете ранее использовавшийся пароль.

## Обязательная проверка до обновления рабочих адресов

1. Сохранить резервные копии текущих исходников и записать версии всех используемых развёртываний.
2. Установить файлы в редакторы, настроить лист «Доступ». Это пока не меняет опубликованные `/exec`.
3. Создать временные тестовые развёртывания обоих проектов: выполнять от имени владельца, доступ «Все». Проверить в отдельной копии сайта, подставив тестовый URL нормативов **и в index.html, и в judge-access.js**, а тестовый URL проекта «Длинная» — для отжиманий и длинного бега. Для проверки записи использовать отдельную тестовую таблицу: заменить ID в JudgeAuth.gs, файлах norm, run и pushup. Пароль/ключ создать в тестовой таблице отдельно.
4. Проверить в настоящем браузере запросы с другого домена: вход, получение JSON, ошибочный пароль, все 11 дисциплин и данные в нужных ячейках. Проверить существующего и нового участника, нулевой результат, время «12:40», смену пароля в другой вкладке и отсутствие сети. Это требуется, потому что локальные тесты не подтверждают настройки доступа/CORS реальных развёртываний Google.
5. Назначить короткий перерыв для переключения: старый клиент не передаёт сеанс и после обновления сервера больше не сможет записывать результаты. Сохранить/выгрузить локальные результаты судей до переключения.
6. Обновить **существующие используемые развёртывания**, выбрав «Новая версия», чтобы сохранить URL. Для отжиманий и бега в одном проекте выбрать одну и ту же новую версию объединённого кода.
7. Опубликовать обновлённые index.html, judge-access.js и sw.js вместе. Проверить вход на рабочих URL и контрольные записи.
8. После проверки архивировать неиспользуемые старые развёртывания, доступные без пароля. Пока они активны, старые адреса могут позволять обход защиты записи. Для отката нужны исходники/номера версий и старая версия сайта; откат также снимает новую защиту.

В сайте сохранены исходные адреса отжиманий `AKfycbxbG5…`, нормативов `AKfycbxMbD8…`, бега `AKfycbxxCw…`: новые присланные адреса автоматически не подставлялись. Перед переключением подтвердить, какие развёртывания реально используются.

## Поведение

Пароль не сохраняется в браузере. В sessionStorage хранится подписанный сеанс сроком до 24 часов, общий для двух серверных проектов через настройки таблицы. Каждый запрос записи проверяет сеанс и текущий пароль. Сайт проверяет доступ каждые 30 секунд, при возвращении на вкладку — заново. При тайм-ауте проверки или отсутствии сети интерфейс блокируется, локально сохранённые результаты остаются. Блокировка при смене пароля появится после следующей проверки (обычно до 30 секунд плюс до 8 секунд на запрос; фоновые вкладки проверяются при возврате).

Сохранение в Google подтверждается только успешным JSON-ответом сервера, а не непрозрачным ответом `no-cors`. Неуспешные отправки остаются в локальном списке и доступны для Excel-выгрузки; автоматической повторной отправки нет. Статический HTML остаётся публичным, доступ к операциям защищает серверная проверка.

## Проверки

`node tests/auth.cjs` — тесты Apps Script с имитацией Google API без доступа к реальной таблице: вход, подпись, отзыв доступа, запись по всем дисциплинам, запрет записи без сеанса и синтаксис JavaScript.
